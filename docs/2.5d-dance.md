# 15 fps dance sprites

The cover renders transparent WebP atlas frames using Canvas 2D. The persistent
music player's currentTime selects the frame, including paused seeks and loops.
Only the selected dance loads. Each actor retains the current and next atlas;
old decoded images are closed. Hidden/offscreen stages sleep. Reduced motion
shows frame zero. Missing assets restore the decorative static couple.

Run `npm run sprites` to rebuild public/dance from the existing 30 fps reference
tracks and painted character assets. BAD covers 27.4 seconds (411 frames), BANG
covers 28.444444 seconds (427 frames), for each actor. Cells are 256x384, sixteen
per atlas. The BANG tutorial timing remains documented in reference-dance-review.md.
The repaired bridal dress is in src/assets/chibi/dance; the other painted layers
remain shared with the non-dancing illustrations.

## Quality status

This is an initial sprite implementation, not a verified 95% choreography match.
The input tracks are prior pose estimates, not a fresh extraction from the videos.
The renderer is front-facing; fingers, profile turns and cloth motion are
approximations. Visual acceptance requires comparison against both source videos.
Do not claim 95% similarity based on clock or frame-index unit tests.

## Cleanup

Removed the dance-only Three.js implementation, two GLB models, intermediate
output/dance-rebuild material and its four obsolete preparation scripts. Git
history retains these sources. Three.js and the opening-door implementation stay.
This removes about 90 MB of tracked intermediate/model files before adding sprites.

## Validation

Run `npm run lint`, `npm test`, `npm run build`. Browser review must cover both
songs, seek while paused, loop boundaries, switching during image loading,
reduced motion, slow/failed atlas requests and mobile layout. Also verify that
no models/wedding or dance3d resources are requested.

## Larger mobile presentation

The mobile portrait is now up to 250 px wide (64vw) and actors render 19% larger
inside the canvas, with a tighter gap. This makes each character roughly 50%
larger on a 390 px-wide phone. Limbs use a single rounded joint silhouette,
subtle edge highlights, shaped palms/fingers and shoes that stay level relative
to the pelvis instead of rotating with the shin. Hip attachment points match the
sampler's grounding calculation. Source timestamps and 15 fps playback stay intact.
